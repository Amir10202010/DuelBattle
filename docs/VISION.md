# Камера и автоматический судья

Все режимы оцениваются сервером. Голосование за чужой ответ отключено, включая старые сообщения WebSocket.

## Что видит игрок

На камере работают MediaPipe Pose Landmarker Lite, Hand Landmarker и EfficientDet Lite0: линии тела и пальцев, рамки предметов. Подсвечивается **только своя камера**. Раньше тот же worker разбирал ещё и присланные кадры соперника: это вдвое снижало частоту на своём изображении и рисовало скелет поверх картинки, которая уже отставала, поэтому контуры не совпадали с человеком.

Worker работает в режиме VIDEO и просит GPU-делегат, с откатом на CPU. Кадры берутся по `requestVideoFrameCallback`, то есть по реальным кадрам камеры, а следующий отправляется сразу после ответа предыдущего — частота получается такой, какую машина действительно вытягивает. Детектор предметов, самый дорогой и с самым медленным сюжетом, запускается на каждом четвёртом кадре. Вкладка в фоне не запускает новые вычисления; таймер-подстраховка возвращает цикл к работе, когда вкладка снова видна.

Координаты нормализуются относительно **всего кадра камеры**, а не обрезка, который отдали модели. Оверлей — это canvas внутри самого окна камеры, и он пересчитывает точки тем же `object-fit: cover`, каким браузер показывает видео рядом. Именно это несовпадение трёх систем координат раньше уводило точки в сторону от человека. Между вычислениями рисование сглаживается фильтром one-euro и идёт на каждом кадре экрана, поэтому движение плавное, а неподвижная рука не дрожит. Текущая частота показана рядом с переключателем подсветки.

Подсветку можно выключить; при неподдерживаемом устройстве игра продолжает работать.

Рамка «у руки» означает близость в изображении, а не доказанный захват. У детектора ограниченный словарь: ручка или точилка могут не получить название в прямом эфире. Цветовая область подсвечивается отдельно. Проверенное AI название появляется в результате, иначе используется «предмет». Идентификация личности не выполняется.

## Как считается результат

1. Сервер принимает один JPEG на раунд и проверяет формат, размер, участника и время.
2. Цвет проверяется по связанным областям относительно исходного кадра. Компенсация освещения и маска неподвижного фона подавляют шум и небольшое смещение камеры. Маленький предмет не сравнивается с площадью движущегося тела.
3. Для AI заданий два отдельных запроса одновременно получают анонимные фотографии и исходные кадры. Цветовой ответ дополнительно получает вырезанный сервером фрагмент предмета. Оба запроса сейчас используют один настроенный провайдер, а не разные модели.
4. Строгая схема, границы оценок, уверенность и согласованность проверяются сервером. Цветовой балл вычисляется по оттенку и насыщенности; размер сверх минимально различимой области не даёт бонуса. Для остальных AI задач учитываются выполнение и ясность ответа.
5. Разница больше 3 баллов определяет победителя. При близких ответах решает серверное время подачи; полное равенство — ничья. До двух ответов или окончания таймера раунд остаётся открытым.

Если AI недоступен, цветовой раунд может завершиться по двум серверным проверкам камеры. Без полного набора проверяемых ответов раунд пропускается.

Отдых судьи различает причины. Сбой провайдера — исчерпанная квота, отказ ключа, недоступный сервис — снимает AI с раунда на 30 секунд. Непонятная пара фотографий не говорит ничего о следующей паре и отдыха не даёт: раньше один размытый ответ отключал судью на две минуты, а вместе с ним и раунды с позами, которых без судьи не бывает.

Расхождение двух проверок тоже больше не отменяет раунд целиком. Если проверки не сошлись в том, засчитан ли ответ, ответ **этого** игрока считается незасчитанным, а соперник спокойно забирает честно выигранный раунд. Численные оценки сверяются только когда обе проверки признали ответ, иначе одно расхождение считалось бы дважды. Неуверенное чтение (ниже порога уверенности) не приносит очка тому фото, к которому относится, и ничего не делает со вторым.

Матч с непроверенным раундом не меняет рейтинг/XP. Фото в базе не сохраняются, журнал оценки содержит только метаданные.

Без `GEMINI_API_KEY` доступны задания камеры. С ключом добавляются предметы, свои задания и подборка коротких раундов с позами, гримасами и сценками — больше тридцати штук. Два раунда из трёх берутся из неё: первый, четвёртый и седьмой ищут настоящий предмет, между ними идут задания, для которых не нужно ничего, кроме самого игрока.

Задания намеренно дурацкие: показать язык, изобразить кошку с лапками, состроить лицо злодея, показать ножку в носке. Граница проходит по телу — ничего не просит раздеться, показать интимное или соревноваться внешностью. Проверяется выполнение жеста, а не привлекательность или особенности тела.

## Сборка и Render

Нужен Node.js 24.16+. `npm run dev` и `npm run build` автоматически вызывают `npm run vision:prepare`. Три модели скачиваются с официального хранилища Google с проверкой SHA-256; версия MediaPipe закреплена в package-lock. Worker собирается в классический JS: это позволяет его WASM загрузчику одинаково работать в dev и production.

Модели и WASM попадают в клиентскую сборку и отдаются с того же домена. Первый запуск подсветки загружает около 30 МБ, затем работает кеш. Бинарные файлы не коммитятся. При изменении кода worker во время разработки повтори `npm run vision:prepare` и перезагрузи страницу.

На Render используется прежний Dockerfile: Python, GPU и YOLO сервис для этой реализации не нужны. Для полного набора заданий укажи `GEMINI_API_KEY` только в переменных сервера, затем сделай redeploy. Опциональный существующий YOLO сервис остаётся источником подсказок AI. Ограничения бесплатного Render на сон сервиса и непостоянный диск сохраняются — см. [DEPLOYMENT.md](DEPLOYMENT.md).

## Проверка

Автоматические проверки охватывают небольшой цветной предмет рядом с движущимся рукавом, шум, изменение освещения, сдвиг камеры, неправильный цвет, сравнение качества, отказ AI, старые голоса, выбор игровых заданий и настоящие WebSocket сообщения. Это синтетические изображения и тестовые ответы провайдера. Камера на реальных устройствах и живой AI требуют отдельной проверки владельцем; браузерная проверка в этой задаче не выполнялась по его просьбе.

Документация моделей: [MediaPipe Pose](https://developers.google.com/edge/mediapipe/solutions/vision/pose_landmarker), [Hands](https://developers.google.com/edge/mediapipe/solutions/vision/hand_landmarker), [Object Detector](https://developers.google.com/edge/mediapipe/solutions/vision/object_detector).
