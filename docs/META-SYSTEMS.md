# Лобби, прогресс и платежи

Состояние на 24 сентября 2026. Задания, сезон, календарь, сундуки, магазин и платежи работают поверх прежних React-клиента, игрового автомата, HTTP/WebSocket-сервера и SQLite. Одна учётная запись и одна база обслуживают браузер и Telegram Mini App. Порядок запуска: [LAUNCH.md](LAUNCH.md).

## Игровой цикл

Главный экран → выбор режима → камера и матч → результат → задания, сезон и награды → экипировка или следующий матч. Гости могут играть, но для начисления прогресса по обычному матчу оба участника должны войти в аккаунт. Уход из матча не даёт ушедшему игроку награды и прогресс заданий; победителем считается оставшийся игрок, даже если до выхода счёт был другим.

Обычные матчи сохраняют статистику без изменения рейтинга. Для наград действуют ограничения: 12 зачётных обычных матчей на аккаунт за день UTC и 5 на пару соперников за скользящие 24 часа. Результат объясняет ограничения. Повторная обработка того же матча не начисляет повторные опыт, статистику, задания, предметы или сезонные очки; квитанции сохраняются и после очистки старых заданий.

Сервер ведёт стартовые, ежедневные и недельные задания; семидневный календарь продолжает последовательность после пропуска дня. Сезон длится 42 дня, включает 30 уровней по 500 очков и бесплатную/платную дорожки. Каталог и баланс находятся в `packages/shared/src/meta`, косметика — в `packages/shared/src/cosmetics.ts`. После первого авторского сезона автоматически работают сезоны с валютой и сундуками; для новых уникальных образов нужно наполнить каталог.

Сундуки разыгрываются на сервере с сохранением результата. Магазин показывает вероятности до покупки; если подходящих невыданных предметов больше нет, действует компенсация 150 монет. Повтор доставки той же награды возвращает первоначальный результат, а не повторную компенсацию.

## Клиент и ошибки

`useMeta` синхронизирует кошелёк, задания, календарь, пропуск и покупки. Защита от двойного нажатия срабатывает сразу; ответы предыдущего аккаунта и устаревшие фоновые запросы не перезаписывают текущее состояние. Покупка пропуска обновляет баланс даже при пустом списке выдаваемых предметов. День, неделя и сезон обновляются по границам UTC.

На главной, в магазине и пропуске есть ошибки с повтором загрузки. Оплата отслеживается по конкретному заказу, включая Stars; неизвестный результат платежа не выдаётся за отсутствие списания. Награды раскрываются последовательно в модальном диалоге с управлением фокусом; пропуск анимации отменяет её оставшиеся таймеры. Общие звуки интерфейса и музыка подключены также в Mini App.

## Подключение платежей

Сначала используй тестовые ключи Stripe и отдельную тестовую базу. Для карточной оплаты нужны `APP_ORIGIN` с публичным HTTPS-адресом, `STRIPE_SECRET_KEY` и `STRIPE_WEBHOOK_SECRET`. Вебхук: `POST /api/pay/stripe/webhook`. Подпишись на события:

- `checkout.session.completed`
- `checkout.session.async_payment_succeeded`
- `checkout.session.async_payment_failed`
- `checkout.session.expired`
- `charge.refunded`

Выдача проверяет подпись вебхука, идентификатор сессии, аккаунт, заказ, валюту и точную сумму. Переход на страницу успеха сам по себе награды не выдаёт. Для одноразовых предложений незавершённый заказ переиспользуется в пределах 24 часов; оплаченная покупка остаётся одноразовой. Окно соответствует стандартному сроку Stripe Checkout: [документация Stripe](https://docs.stripe.com/payments/checkout/managing-limited-inventory).

Stars используют настройки из [telegram.md](telegram.md). Payload счёта содержит конкретный заказ. Pre-checkout проверяет аккаунт, цену, валюту XTR и срок счёта; выдача происходит только после подтверждённого `successful_payment`. Повтор сообщения безопасен. Ошибка транзакции возвращает ошибку вебхука и освобождает квитанцию обработки для повторной доставки. Требование подтверждённого платежа: [Telegram Stars](https://core.telegram.org/bots/payments-stars).

Частичный возврат Stripe уменьшает учтённую выручку, но сохраняет содержимое покупки. Полный возврат отзывает выданные предметы/доступ и доступный остаток выданной валюты. События могут прийти повторно или до подтверждения оплаты: накопленная сумма возврата не уменьшается, полностью возвращённый заказ не выдаётся. Stripe использует `charge.refunded` также для частичных возвратов: [справочник событий](https://docs.stripe.com/api/events).

Ограничение возвратов: уже потраченную валюту можно списать только в пределах текущего баланса; отрицательный долг и отслеживание всех производных покупок не реализованы. Проверка живого платёжного провайдера перед запуском обязательна: локальные тесты проверяют обработчики и протоколы, но не подтверждают настройку реального мерчант-аккаунта.

## Данные и эксплуатация

Миграции 6–7 добавляют таблицы и колонки без сброса существующих кошельков. Сохраняются квитанции матчей, выдач и покупок; добавлены накопленные суммы возвратов. Перед обновлением рабочей базы сделай резервную копию по [DEPLOYMENT.md](DEPLOYMENT.md). Тесты используют отдельные базы.

Страница `/admin` и API `/api/admin/kpis` доступны только разрешённым аккаунтам: `ADMIN_EMAILS` для веб-аккаунтов и `TELEGRAM_ADMIN_IDS` для Telegram. Метрики основаны на SQLite и событиях приложения. Завершение стартовых заданий учитывает весь набор; выручка учитывает частичные возвраты; покупка валюты сама по себе не считается покупкой косметики. Оценки выручки Stars и LTV приблизительные; клиентские события зависят от доставки и блокировщиков.

`compose.yaml` передаёт платёжные, почтовые и Telegram-настройки серверу. Активные комнаты и очереди по-прежнему живут в одном процессе; перезапуск прерывает текущие матчи. Горизонтальное масштабирование требует отдельной работы.

## Локальная проверка

Нужен Node.js 24.16+. `npm run dev:sandbox` отключает внешние интеграции и использует `data/sandbox`, не изменяя операторский `.env`.

```sh
npm test
npm run test:integration
npm run typecheck
npm run lint
npm run build
npm run test:smoke
```

Общий набор включает серверные HTTP/WebSocket-интеграции; отдельная команда удобна для их повторного запуска. Smoke запускает собранный production-сервер с временной SQLite-базой, проверяет health/readiness, SPA-маршруты, CSP, закрытые API и отключённый платёжный вебхук, затем удаляет только созданную им временную базу.

Результаты последнего прогона записаны в [RELEASE-CHECKS.md](RELEASE-CHECKS.md). Браузерные AI-прогоны не выполнялись по запросу владельца. Живые камеры на двух устройствах, настоящий AI, платежи у провайдеров, Linux Docker-образ, HTTPS-хостинг и нагрузка требуют отдельного окружения; эта итерация их готовность не подтверждает.
