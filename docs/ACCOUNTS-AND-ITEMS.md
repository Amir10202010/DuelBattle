# Аккаунты, герои и магазин

## Локальный запуск

Нужен Node.js 24.16+. В корне проекта:

```sh
npm ci
# Скопируй .env.example в .env, если своего .env ещё нет.
npm run dev
```

Открой http://localhost:5173. В разработке без почтового ключа код подтверждения
показывается прямо в форме. Он создаётся сервером, действует 10 минут и используется
один раз. В `NODE_ENV=production` этот режим отключён.

## Что настроить перед публикацией

1. Сделай резервную копию SQLite. При запуске добавятся таблицы кошельков, инвентаря,
   операций и подтверждения входа. Старые аккаунты и результаты сохраняются.
2. Укажи `APP_ORIGIN=https://твой-домен` без завершающего `/`,
   `NODE_ENV=production` и постоянный `DATA_DIR`. В Docker Compose origin берётся из `DOMAIN`.
3. В Google Cloud создай OAuth client типа **Web application**. Настрой consent screen
   и добавь точный Authorized redirect URI:
   `https://твой-домен/api/auth/google/callback`.
   Для разработки добавь `http://localhost:5173/api/auth/google/callback`.
   Пока OAuth-приложение в режиме тестирования, добавь нужных пользователей в Test users;
   для открытого запуска настрой публикацию в кабинете Google.
4. Сохрани `GOOGLE_CLIENT_ID` и `GOOGLE_CLIENT_SECRET` в переменных **сервера**.
5. Настрой отправку кода подтверждения — одним из двух способов.
   **Если домен есть:** в Resend подтверди домен отправителя, добавь серверные
   переменные `RESEND_API_KEY` и `MAIL_FROM`, например `DuelBattle <play@твой-домен>`.
   **Если домена нет** (сайт на чужом поддомене): в Brevo подтверди один адрес
   отправителя — подойдёт личная почта — и добавь `BREVO_API_KEY` и `MAIL_FROM`,
   например `DuelBattle <твоя-почта@gmail.com>`. Адрес в `MAIL_FROM` должен быть
   ровно тем, который подтверждён. Если заданы оба ключа, используется Resend.
6. Выполни `npm run build`, перезапусти приложение и открой `/api/auth/providers`:
   настроенные способы входа должны возвращать `true`.
7. На опубликованном домене один раз проверь свой Google-вход и получение письма,
   затем выход, повторный вход и восстановление пароля. Реальные OAuth и доставка писем
   зависят от настроек твоих кабинетов; локальные тесты их не заменяют.

Для Render эти значения задаются в **Environment** сервиса. Укажи адрес своего
сервиса в APP_ORIGIN и callback Google. Хранилище базы должно переживать деплой:
если тариф не предоставляет постоянный диск, аккаунты и покупки могут пропасть
при пересоздании сервиса. Полный запуск: [DEPLOYMENT.md](DEPLOYMENT.md).

Без настроенного почтового сервиса новая email-регистрация в production закрыта.
Вход в уже существующий аккаунт по паролю продолжает работать. Новый email-аккаунт
создаётся только после проверки кода. Пароль — от 12 до 128 символов. Есть лимиты
попыток, пауза между письмами и отзыв старых сессий после сброса пароля.

Google использует Authorization Code + PKCE, одноразовый state, nonce и проверку
подписи ID token, issuer, audience, срока действия и подтверждённой почты. Пароли и
ключи не попадают в клиент. Сессия хранится в HttpOnly cookie, Secure в production.
Если почта уже занята email-аккаунтом, автоматического объединения нет: войди по почте.
Старые аккаунты доступны через «Войти по старому ID» и прежний код восстановления.

Документация провайдеров: [Google OpenID Connect](https://developers.google.com/identity/openid-connect/openid-connect),
[проверка Google ID token](https://developers.google.com/identity/gsi/web/guides/verify-google-id-token),
[отправка писем Resend](https://resend.com/docs/api-reference/emails/send-email).

## Игровая петля

Главная → рейтинговый бой → награда → магазин → экипировка → следующий бой.
В магазине 14 предметов, включая бесплатный стартовый набор. Все предметы косметические:
оружие меняет анимацию, но не баллы, оценку камеры или рейтинг.

- Новый кошелёк: 160 Battle коинов один раз.
- Ежедневный подарок: 30 коинов, новый день считается по UTC.
- Зачётный рейтинговый матч: 20 коинов + 5 за каждую победу текущей серии, максимум +20.
- Первый зачётный матч дня: ещё 30. Каждый новый уровень: 40. Новое достижение: 20.
- На третьем уровне открывается эффект «Звёздная пыль».

Гостевые, дружеские и незачётные матчи не приносят валюту. Повторные начисления за
тот же матч и подарок отклоняются по уникальному идентификатору операции. Лимит
зачётных матчей с одной парой соперников сохраняется. Цена берётся из серверного
каталога; списание и получение предмета выполняются в одной транзакции. Повторная
покупка уже купленного предмета ничего не списывает.

Герой состоит из основы, одежды, волос, аксессуара, оружия, ауры и финального эффекта.
В профиле можно примерить, надеть и снять необязательные слои. Примерка не меняет
экипировку до нажатия кнопки. В бою используется сохранённый сервером комплект.
Обычная атака длится около секунды, финальная — 1,4 секунды. Управление не блокируется;
при reduced motion остаётся спокойное обозначение результата.

## Где расширять

- `packages/shared/src/cosmetics.ts` — каталог, цены, слоты и типы.
- `packages/server/src/economy.ts` — выдача, покупки и экипировка.
- `packages/server/src/database.ts` — миграции и ограничения SQLite.
- `packages/client/src/components/avatar` — SVG-слои, главный экран и гардероб.
- `packages/client/src/components/battle/DuelActors.tsx` — атаки по результатам сервера.
- `packages/client/src/hooks/useEconomy.tsx` — баланс, запросы и уведомления.
- [AUDIO.md](AUDIO.md) — музыка, эффекты и настройки.

Проверки без браузера: `npm run typecheck`, `npm run lint`, `npm test`, `npm run build`.
