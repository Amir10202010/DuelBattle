# DuelBattle

Игра в поиск предметов через веб-камеру: два игрока получают одно задание, показывают ответ и делают снимок. Выигрывает ответ, который лучше подходит заданию; при близких баллах решает скорость. По умолчанию матч идёт до трёх побед.

Обычная игра и комнаты с друзьями работают без рейтинга. В рейтинговом режиме сервер проверяет ответы, сохраняет результат, начисляет опыт и открывает награды. Игроки не оценивают ответы друг друга.

## Запуск для разработки

Нужен Node.js **24.16 или новее**.

```sh
npm ci
cp .env.example .env
npm run dev
```

В PowerShell вместо `cp` можно использовать `Copy-Item .env.example .env`.

Открой `http://localhost:5173`. Сервер работает на порту 8787, Vite проксирует HTTP API и WebSocket. Файл `.env` в корне загружается сервером автоматически. Не перезаписывай свой существующий `.env`.

Порты в разработке задаются парой `CLIENT_PORT` и `SERVER_PORT`: Vite слушает первый и проксирует на второй, и сервер в разработке тоже слушает `SERVER_PORT`. Так обе половины `npm run dev` не разъезжаются, даже если в окружении уже лежит чужой `PORT`. В production `SERVER_PORT` игнорируется и порт задаёт только `PORT` — иначе забытая строка в `.env` увела бы деплой не на тот порт.

По умолчанию dev-сервер сохраняет базу в `packages/server/data/battle.sqlite`: путь `DATA_DIR` считается от рабочей папки процесса. При запуске `npm start` из корня этот же относительный путь указывает уже на корневую `data`. Для одной и той же базы задай **абсолютный DATA_DIR**. Docker использует собственный постоянный том.

## Что есть в игре

- Быстрый поиск соперника, отдельная рейтинговая очередь, приглашения по ссылке и свои задания в дружеских комнатах.
- Вход через Google или почту с подтверждением шестизначным кодом, восстановление пароля и короткое знакомство с игрой. Старые ID и коды восстановления продолжают работать. Для production нужны настройки Google и почтового сервиса: [инструкция](docs/ACCOUNTS-AND-ITEMS.md).
- Пять калибровочных матчей, восемь рангов, опыт, ежедневный бонус, достижения и история. Данные настоящие, источник — сервер и SQLite.
- Главный экран с героем, послойная SVG-экипировка, Battle коины, магазин и ежедневные подарки. Покупки, баланс и награды хранятся на сервере. Оружие и эффекты меняют внешний вид, а не результат боя.
- Очко запускает короткую атаку героя в полосе под камерами; победа в матче — отдельный нокаут во весь экран с именем проигравшего. Есть повышение ранга, серии и реванш. На лендинге тихо; внутри игры музыка и звуки запускаются автоматически, если браузер разрешает. Настройки звука и уменьшения анимации учитываются.
- Светлая неоновая и тёмная темы; английский и русский. По умолчанию используются настройки устройства, ручной выбор сохраняется в браузере.
- Живое видео соперника идёт примерно пятнадцать кадров в секунду: кадры берутся по кадрам камеры, декодируются заранее и рисуются на canvas, а при забитом канале отправка пропускает кадр, чтобы картинка отставала не больше, чем нужно.
- Английский каталог содержит больше тысячи заданий. Русскоязычные матчи используют отдельную проверенную подборку переведённых заданий из этого каталога. В смешанной комнате оба видят одно и то же задание на своём языке. Пользовательские задания сохраняются как написаны.

- Бот и Mini App в Telegram: вход по подписанному `initData` без пароля, профиль, рейтинг, история, таблица лидеров, вызовы друзей по ссылке, приглашения, задания дня, серии дней, уведомления о результате, Premium за Telegram Stars. Тот же аккаунт и та же арена, что и в браузере. Без `TELEGRAM_BOT_TOKEN` ничего из этого не создаётся и игра работает как прежде: [docs/telegram.md](docs/telegram.md).

Подсветка тела, рук и предметов на своей камере, последние пять секунд, три десятка коротких дурацких заданий и сравнение ответов: [как работает новая проверка](docs/VISION.md).

## Проверка ответов и честность

Цветовые и другие поддерживаемые задания проверяются по снимку на сервере. Для AI-заданий работают две отдельные проверки, строгая схема ответа, пересчёт баллов и проверка расхождений. Сейчас обе проверки используют один настроенный провайдер; это не два независимых поставщика моделей.

При ненадёжной проверке рейтинговый матч не меняет рейтинг и опыт. Клиент не присылает итоговый счёт. Повторные снимки, поздние ответы, чужие сессии, попытки оценить рейтинговый ответ голосованием и повторная запись результата отклоняются. Есть ограничение на повторные зачётные матчи с одной парой соперников и временный запрет рейтинговой очереди после выхода из активного матча.

Без AI-ключа все комнаты используют задания, проверяемые камерой. С ключом доступны свои задания и смешные раунды с жестами и предметами. Это позволяет развернуть приложение без платного провайдера и подключить его позже.

Эти меры ограничивают злоупотребления, но веб-камера в браузере не доказывает присутствие реального предмета. Подставное видео, дополнительные аккаунты и ошибки моделей полностью не исключены. Реальная нагрузка и живой AI требуют отдельной проверки перед большим запуском.

## Данные и безопасность

SQLite: WAL, транзакции, ограничения уникальности и индексы. Миграции выполняются при старте; прежний `profiles.json` импортируется один раз. Повреждённые данные не заменяются пустой базой. Для переноса старого профиля в аккаунт требуется его подписанный токен.

Пароли хешируются scrypt. Сессионные токены хранятся в базе в виде хеша; браузер получает HttpOnly cookie, Secure в production. Изменяющие auth-запросы требуют допустимый Origin и специальный заголовок. Клиенту не отдаются пароли, внутренние идентификаторы аккаунтов или AI-ключи.

Фото транслируются сопернику, а для AI-проверки снимки также отправляются настроенному провайдеру. На сервере нет архива фото: для диагностики сохраняются только метаданные оценки. Условия хранения у внешнего провайдера нужно учитывать в своей политике приватности. Микрофон не используется.

## Команды проекта

```sh
npm run typecheck
npm run lint
npm test
npm run build
npm start
```

CI выполняет проверки и поднимает собранный production-сервер для проверки HTTP: `/healthz`, `/readyz` и отдача клиента. Матч с камерой в CI не проигрывается — его закрывают серверные end-to-end тесты на двух сокетах.

## Архитектура

- `packages/shared` — типизированный игровой автомат, задания, проверка сообщений, рейтинг и достижения.
- `packages/server` — HTTP/WebSocket, аккаунты, подбор соперников, SQLite, проверка фото и AI.
- `packages/client` — React, камера, игровые экраны, темы, локализация и звуки.
- `packages/server/src/telegram` — бот, Mini App API, вебхук, уведомления, платежи и админ. Отдельного сервера и второй базы пользователей нет.
- `packages/client/src/telegram` — Mini App на маршруте `/tg`: свой корень и своя навигация, но те же токены дизайна, тот же сокет и тот же экран матча.
- `vision` — необязательный сервис распознавания объектов; основной игре не нужен.

Активные комнаты и очередь находятся в памяти **одного процесса**. База и аккаунты переживают перезапуск, текущий матч — нет. Не запускай несколько копий сервера за балансировщиком: для этого сначала понадобится общая система комнат, очередей и ограничений запросов.
